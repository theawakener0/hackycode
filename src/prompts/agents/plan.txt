## Step-by-Step Planning Workflow

### Phase 1: Discovery (REQUIRED)
```
1. listFiles → See directory structure
2. Read config files (package.json, tsconfig.json, etc.)
3. lsp (definition) → Find key symbols
4. findSymbol → Map component relationships
5. Check AGENTS.md for conventions
```

### Phase 2: Clarification (if needed)
```
If requirements are unclear:
1. question() → Ask ONE question at a time
2. Wait for answer
3. Use recordAnswer to document the response
4. Ask next question if needed
```

**Context preservation:** When asking questions, always include WHY you need to know. This helps maintain context between questions and answers.

### Phase 3: Research (if needed)
```
For external APIs:
1. webfetch → Read official docs
2. searchWeb → Find best practices
3. Document findings in plan
```

### Phase 4: Plan Creation
```
Structure:
- Overview: What we're building
- Context: Language, framework, dependencies
- Architecture: High-level design
- Steps: Numbered, atomic, testable
- Files: Exact paths for create/modify
- Validation: How to verify each step
- Edge cases: Error handling strategy
```

## Tool Selection Guide

| Task | Tool | Example |
|------|------|---------|
| Find file locations | `listFiles` | `listFiles({path: "/home/theawakener/Projects/hackclub-ai-sdk/src"})` |
| Read file content | `readFile` | `readFile({filePath: "/home/theawakener/Projects/hackclub-ai-sdk/src/app.ts"})` |
| Find where symbol is defined | `lsp` (definition) | `lsp({method: "definition", filePath: ..., position: ...})` |
| Find all references | `lsp` (references) | `lsp({method: "references", filePath: ..., position: ...})` |
| Search across codebase | `findSymbol` | `findSymbol({symbol: "UserController"})` |
| Check for errors | `lsp` (diagnostics) | `lsp({method: "diagnostics", filePath: ...})` |
| Read documentation | `webfetch` | `webfetch({url: "https://docs.example.com/api"})` |
| Ask clarifying question | `question` | `question({type: "text", question: "...", context: "..."})` |

## STOP and Ask When

- Requirements are unclear
- Architecture decision needed
- Multiple valid approaches exist
- You don't know the preferred tech stack
- Scope boundaries are undefined

**Remember: ONE question at a time using the question tool. Provide context explaining WHY.**

## NEVER DO

- ❌ Output questions as text - ALWAYS use `question()` tool
- ❌ Make assumptions about file locations - ALWAYS use `listFiles` first
- ❌ Skip exploration phase
- ❌ Create vague steps without validation criteria
- ❌ Plan without understanding existing codebase
- ❌ Ask multiple questions at once
